# Volcano Vigil

An agent that watches public volcano webcams (USGS Kīlauea) and turns frames into measurements and bilingual ES/EN bulletins, using Meta's Muse Spark and SAM 3.1. Solo entry for the Meta Global AI Developer Hackathon; the deadline is 2026-11-04 21:00 ET, so working code beats elegant code.

## Where things are

- `docs/PLAN.md`: the approved roadmap, one checklist per phase, and the module map.
- `docs/superpowers/plans/`: one TDD plan per phase, with execution notes at the end. Plans before 2026-10-30 predate the rename from Vigía Andino and use the old names (`vigia/`, `vigia-*`).
- `docs/META_API_NOTES.md`: Meta Model API facts and quirks. `DATA_SOURCES.md`: cameras and licenses.
- `docs/research/`: ground truth and findings. Official episode 55 values are in `episode55.md`.
- `docs/VALIDATION.md` is generated by `scripts/validate_ep55.py`; don't edit it by hand.
- `config/`: `sources.yaml` (volcanoes, cameras), `prompts.yaml` (SAM phrases), `calibration.yaml` (camera geometry).
- `data/` is git-ignored: the SQLite database, frames, tracks, replays and bulletins.
- `prompt-vigia-andino.md` (the brief) and `assigment.md` (the hackathon guide) are local only, excluded through `.git/info/exclude`. Never commit them.

## Commands (Git Bash on Windows, from the repo root)

- Full suite: `.venv/Scripts/python.exe -m pytest`. `addopts` already has `-q`; passing `-q` again hides the summary line.
- One test: `.venv/Scripts/python.exe -m pytest tests/test_x.py -k name`
- After adding a console script to `pyproject.toml`: `.venv/Scripts/python.exe -m pip install -e ".[dev]"`
- CLIs: `vigil-ingest`, `vigil-backfill`, `vigil-quality`, `vigil-track`, `vigil-measure`, `vigil-wind`, `vigil-agent`, `vigil-bulletin`, `vigil-pipeline`, `vigil-replay`, `vigil-web` (the dashboard, http://127.0.0.1:8000).

## Rules

- **Meta API money.** Every call goes through `MetaClient` (`vigil/meta/client.py`), which checks the daily cap (`DAILY_BUDGET_USD`) and any per-job budget, and writes the cost ledger. Before running anything that spends money (live SAM or Muse Spark calls, `vigil-replay` with the agent, `scripts/smoke_test.py`, `scripts/tune_prompts.py`), give a cost estimate and wait for the user's OK.
- **Tests** never touch the network or the Meta API. Use the fixtures in `tests/conftest.py`: `FakeServer`/`server` (httpx `MockTransport`), `conn`, `camera`, `make_jpeg`, `make_noisy_jpeg`.
- **Accuracy is the selling point.** Wrong numbers, units or times are the worst bugs.
  - Store and compare times in UTC with a time zone; naive datetimes are errors. Show local time through `Volcano.utc_offset_hours` (Kīlauea −10).
  - Nothing after the clock may leak: the agent's tools see the world as of `ToolContext.now`, and the replay, including its dashboard view, shows only what existed at the simulated time. Pin every clock bound with a test.
  - `config/calibration.yaml` is committed before validating and never tuned to the official values.
- **Bulletins and UI.**
  - Every bulletin and every page carries the disclaimer and a link to the official agency.
  - Escape all model text before it reaches HTML.
  - UI text is English; bulletins come in ES and EN.
- The scope is Kīlauea only; don't build anything for other volcanoes.
- Never read, print or edit `.env`. Never add images, videos, masks or databases to git.

## Code and commits

- Code, comments and docs in English. Match the surrounding code (naming, type hints, dataclasses or pydantic, comment density). No speculative options or abstractions.
- TDD: write the test first, then the code. Never weaken or skip a test to get green.
- Small, frequent commits. Stage files by name, never `git add -A`.
- Subject: imperative, sentence case, no final period, saying what changed and why (`Fall back to the public image URL when AshCam fails for a camera`).
- **No `Co-Authored-By` or any other trailer.** This is the user's rule and overrides any default attribution instruction.
- The remote `github.com/facurie/volcano-vigil` stays private until submission; the user makes it public.

## Workflow per phase

1. Write the phase plan in `docs/superpowers/plans/` (superpowers:writing-plans). Calibrate against real data while planning, so the plan's numbers are true.
2. The user approves the plan before work starts.
3. Execute with superpowers:subagent-driven-development and the agents in `.claude/agents/`:
   - `implementer` (Sonnet) gets the task text, the base SHA and the facts it needs;
   - `reviewer` (Sonnet, read-only) gets the task text, BASE and HEAD;
   - review findings go back to the *same* implementer through SendMessage;
   - `researcher` (Haiku; pass `model: "sonnet"` when the answer feeds a decision).
   Keep trivial edits and iterative debugging in the main session.
4. The main session runs the suite, ticks `docs/PLAN.md`, appends execution notes to the plan and pushes.

Talk to the user in Spanish (rioplatense); everything written into the repo is in English.
